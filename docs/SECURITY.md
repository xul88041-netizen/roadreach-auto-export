# RoadReach Auto Export Security Boundary

## Public data boundary

Anonymous browsers receive the Supabase project URL and publishable key. Both are public identifiers, not secrets. RLS and grants remain mandatory.

Anonymous users can:

- Select `public.public_vehicle_catalog`.
- Read only vehicles with `publication_status = PUBLISHED`, or `SOLD` records less than 90 days old.
- Read the explicit safe vehicle fields used by the security-invoker view.
- Read public image URLs from the `vehicle-images` bucket.
- Submit an inquiry through the `submit-inquiry` Edge Function.

Anonymous users cannot select the full `vehicles` record. The safe view intentionally omits:

- `full_vin`
- every internal RMB cost
- `total_other_cost_rmb`
- `target_profit_rmb`
- `suggested_fob_price_usd`
- expected profit and margin
- all inquiry, customer, email, follow-up, quote and deal data

The inquiry Edge Function applies field allowlisting, length limits, email validation, a honeypot and a hashed 5-per-15-minute fingerprint limit. It then calls a service-role-only database transaction. Raw IP addresses are not stored.

## Administrator data boundary

Admin access requires both:

1. A valid Supabase Auth email/password session.
2. A matching enabled row in `admin_allowlist` checked by `is_admin()`.

The initial allowlist contains only `xuli58836@gmail.com`. RLS policies on all operational tables use `is_admin()`. A signed-in Supabase user who is not allowlisted receives no admin table access.

The public frontend never receives an elevated key. Edge Functions use only the `ROADREACH_SERVICE_KEY` Supabase Function Secret for controlled server-side transactions and external integration. References to PostgreSQL's `service_role` in the migration are database-role grants, not browser credentials.

## RLS policy summary

- `admin_allowlist`: allowlisted administrator can read.
- `vehicles`: administrator CRUD; anonymous select only for the published/recently-sold row condition and only through granted safe columns/view.
- `vehicle_images`: administrator CRUD; anonymous select only where the parent vehicle is public.
- `customers`, `inquiries`, `followups`, `quotes`, `deals`, `customer_email_messages`, `gmail_sync_state`: administrator CRUD only.
- `inquiry_rate_limits`: no browser policies; Edge Function service role only.
- `storage.objects` in `vehicle-images`: authenticated allowlisted administrator can select/insert/update/delete. The bucket is public for object delivery, while mutations remain authenticated.

RLS is enabled on every application table. Table grants use least privilege in addition to RLS. The `public_vehicle_catalog` view uses `security_invoker = true`, so underlying grants and RLS still apply.

## VIN

- `full_vin` exists only on the admin table and is never part of the public view.
- `masked_vin` is generated by the database trigger; it is not trusted as manually entered public text.
- `IN_STOCK` with a sufficiently long VIN produces the first 8 characters, four asterisks and the final 4 characters.
- `AVAILABLE_TO_SOURCE` always produces a null public VIN.
- `request_full_vin` only creates a `VIN REQUESTED` flag. It never sends or reveals a VIN.

## Internal pricing

All RMB input costs, target profit, suggested price, expected profit and expected margin remain on the protected `vehicles` table. Only `public_reference_fob_price_usd` is in the public view. The public page always displays a reference-price disclaimer.

## Secrets

Never commit:

- Supabase secret/service role keys
- administrator passwords
- Gmail client secret or refresh token
- OAuth authorization codes
- private customer exports
- production `.env` files

`.gitignore` excludes `.env` variants except `.env.example`. GitHub repository variables contain only the Supabase URL and browser-safe publishable key. Function secrets are configured with `supabase secrets set`.

## Gmail OAuth

- Production import uses the Gmail API from an authenticated Edge Function.
- OAuth scope is exactly `https://www.googleapis.com/auth/gmail.readonly`.
- The importer does not call Gmail modify, delete, label, trash or send endpoints.
- Client secret and refresh token stay in Supabase Edge Function secrets.
- Only qualified business threads are copied. Attachments store metadata, not binary data.
- The ChatGPT/Codex Gmail connector is not a runtime dependency.

## Remaining operational risks

- Supabase Free Tier and GitHub Pages are external services; availability from mainland China cannot be guaranteed.
- Rate limiting is basic MVP protection, not a managed WAF. Raise protection if abuse occurs.
- A public storage URL can be shared. Do not upload internal-only images to the public bucket.
- The administrator must enable MFA when available, use a unique password, protect the Gmail account and rotate leaked OAuth credentials immediately.
- Review Supabase logs and Auth users periodically. Disable unexpected users and keep public sign-up disabled.
